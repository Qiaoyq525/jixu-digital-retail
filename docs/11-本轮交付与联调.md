## 前端与 Java 的连接

`src/main/resources/static/index.html` 依次加载基础页面模块 `app.js`、会员模块 `member-ui.js` 和员工模块 `staff-ui.js`；对应 CSS 负责页面样式。本地商品图位于 `static/images/products/`，运行时不依赖外部图片服务或 CDN。

浏览器操作通过 `app.js` 中的 `api()` 向同源 `/api/...` 地址发出 HTTP 请求。`api()` 处理 JSON、会话、CSRF 令牌和错误提示。页面只显示金额和状态，真实价格、会员等级、优惠、库存、积分、角色权限均在 Java 中检查。

| 页面动作 | Java 接口与主要职责 |
|---|---|
| 查看商品和分类 | `GET /api/products`、`GET /api/categories`，`CatalogController → CatalogService → CatalogMapper` |
| 修改购物车数量 | `PUT /api/cart`，保存当前会员的商品与数量 |
| 核对订单金额 | `POST /api/orders/preview`，从数据库取价格，按优惠规则试算 |
| 会员提交商品 | `POST /api/queue/join`，保存购物车快照并分配明确柜台与员工，保持等待 |
| 查看等待与柜台 | `GET /api/queue`，按角色读取票据、柜台、员工、商品与试算金额 |
| 收银员确认会员单 | `POST /api/queue/{id}/confirm`，仅指定 SALES 在事务内确认付款并完成票据 |
| 查订单和详情 | `GET /api/orders`、`GET /api/orders/{id}`，服务端按角色限制数据范围 |
| 员工现场选品收银 | `POST /api/orders/checkout`，在事务内保存订单并扣库存 |
| 整单退款 | `POST /api/orders/{id}/refund`，还库存、撤回积分和累计净消费 |

会员界面包含商品搜索、5 类分类、购物车、订单确认、排队进度、结账完成、订单搜索与状态筛选、详情、会员权益。老板与销售员分别有工作概览；员工收银清单显示商品图片并可选择会员。老板还可操作商品和分类、供应商、采购入库、库存流水、账号停用、优惠设置、销售统计、日志和 CSV 导出。

本轮按最新要求改为人工确认：默认 1 号台为小周（cashier1），2 号台为小陈（cashier2）。会员提交后明确显示分配给谁；只有对应销售员在收银工作台确认后，才真正结账。销售员只能查看自己的等待单，老板可查看全店但不能代员工确认。等待单可取消，正常重启后继续保留。

## 这次新增的数据库内容

Flyway SQL 位于 `src/main/resources/db/migration`，启动应用时按版本执行一次。不要随意修改已应用迁移的内容，否则校验和会不一致。

- `V1__create_shop_tables.sql`：14 张业务表和基础设置，包含用户、分类、商品、购物车、订单明细、积分、库存、采购、日志和结账票据。
- `V2__upgrade_to_digital_store.sql`：旧演示资料按条件改为数码零售主题，保留订单关系和业务库存。
- `V3__product_images_and_order_snapshots.sql`：商品新增 `image_url`；订单明细新增 `sku`、`description`、`image_url` 快照。为已有数码库补键鼠分类及 G304、K380s，保留老板修改过的商品和价格。
- `V4__manual_checkout_counters.sql`：新增 `checkout_counter` 固定柜台与员工绑定，支持提交时保存明确归属。旧 V1/V2/V3 文件保持不变。

新空库由 `DemoDataInitializer` 加入 5 个演示账号、5 类商品和 14 款设备。已有库再次启动不会重置商品库存或清空订单。历史订单从未记录过的货号、规格、图片留空，避免把当前设备资料当成旧订单的购买记录。

新订单会保存购买时的名称、单价、数量、货号、规格、图片和优惠。之后编辑商品资料，历史订单仍保留当时内容。当前未提供图片上传；自定义新商品可以使用通用展示。

## 为什么要保留这些 Java 设计

一次购买的核心在 `OrderService`：先校验身份与参数，读取真实商品，锁会员和商品行，计算优惠，然后在同一事务中保存订单、明细、库存流水和积分。失败会回滚，防止只扣库存却没有订单。支付和退款采用一致的锁顺序，降低并发死锁风险。

`QueueService` 管理数据库中的固定柜台、等待票据和人工确认权限。收银员确认与订单事务合在一起，避免状态已完成但库存没有扣减，或订单已付款而票据仍要求重试。独立的 `ConcurrencyDemoService` 保留固定线程池、CountDownLatch、Future 和 ReentrantLock，通过隔离数据展示课程中的线程协作与真实库存竞争。

优惠部分使用 `DiscountPolicy` 接口、抽象策略、具体策略和计算器，可解释接口、继承、多态和组合。创建策略的方式应称为“简单工厂”，不称为工厂方法模式。金额使用 `BigDecimal`；普通 Java 对象保留 getter/setter 和中文说明，请求响应适当使用 `record`。
