**一周内的安排**

以四天完成主体工作、后三天留作修正和练习为目标。每天可按约 2—4 小时安排，理解代码卡住时缩小阅读范围，不靠熬夜把所有文件读一遍。

| 时间 | 主要工作 | 当天应留下的成果 |
|---|---|---|
| 第 1 天 | 确认一页需求；亲自走一遍主流程；读懂商品查询 | 一页需求、主流程记录、自己画的调用链 |
| 第 2 天 | 做异常验收；理解优惠计算、事务和历史订单问题 | 验收表、金额手算、问题记录 |

| 第 4 天 | 整理课程报告与 PPT，串起一次完整演示 | 可阅读的报告、PPT 初稿、演示顺序 |
| 第 5—7 天 | 修正遗漏、核对格式、练习答辩、打包 | 最终报告、PPT、工程资料包 |

如果前两天进展顺利，可以提前进入报告整理。先保存实际操作记录，后面写报告会快很多。

老师强调的“形成 skill（Markdown 文件）”，重点是把你的意图和可验收约束表达清楚。现有 `java-architect`、`architecture-designer` 提供专业方法；项目专用规格则要说明这家数码店到底应该怎样工作。可以复用现有实施约定中的业务部分，删除过时的代理分工和版本说法，再由你确认。

示例规格：

> REQ-01 会员提交购物车后，系统生成 WAITING 票据，并返回收银台与销售员。销售员确认前，不生成支付订单、不扣库存、不增加积分。只有分配到的启用销售员可以确认；其他销售员、会员和老板都不能代为确认。确认失败时，库存、积分和订单应保持一致，不能只完成一部分。

再补三项容易理解的非功能要求：

| 类别 | 你可以确认的要求 | 验证方式 |
|---|---|---|
| 安全 | 会员只能读取自己的订单；前端隐藏按钮之外，接口也要限制权限 | 用另一个账号或接口请求核对拒绝结果 |
| 一致性与恢复 | 确认失败不能留下半笔交易；正常等待单重启后仍保留 | 记录失败前后数据，停止并重新启动应用后查看等待单 |
| 性能 | 在注明的本机配置与演示数据量下，常见操作可顺畅完成 | 选商品查询和订单列表，记录数据量、重复测量的响应时间与局限 |

性能目标由你根据课堂场景确定。可以先测量再决定是否需要优化；没有测过的并发规模或响应时间不要写成已达成指标。

完成标准：把规格交给另一个人，他能依据它判断功能是否正确，不需要猜你的意思。

**任务 5 按三条小路径读 Java**

先读一个方法的输入、处理与输出，再向下追调用。遇到陌生语法，要求 AI 用同一个业务例子解释，每次解释一小段。

| 顺序 | 阅读内容 | 你需要能回答的问题 |
|---|---|---|
| 1 | `Product` 的字段、getter/setter；`Role` 枚举 | 一个对象表示什么？字段为什么是这个类型？对象和数据库表有什么联系？ |
| 2 | `CatalogController.products` → `CatalogService.list` → `CatalogMapper.list` | 浏览器发什么请求？关键词怎么传入？为什么会员只能看到上架商品？SQL 结果怎样变成 JSON？ |
| 3 | `DiscountPolicy`、`AbstractDiscountPolicy`、比例折扣与满减实现、`DiscountCalculator` | 接口是什么？为什么能用同一种调用方式应用不同优惠？为什么金额用 BigDecimal？ |
| 4 | `OrderService` 的结账与退款步骤 | 哪些数据必须一起成功或一起失败？重复点击为什么不能多扣一次？ |
| 5 | `QueueService` 与 `CashierService` 的职责 | 业务等待为什么要人工确认？有待办时为什么不能调岗？两个新增请求同时到达怎样仍不超过四人？ |

前 3 项尽量读懂关键方法；后 2 项先能解释业务目的与调用方向，再深入事务和锁。暂时不要求你读懂 Spring Security 内部实现、全部 SQL、每一段前端代码或 4473 行 Java。

- [ ] 画出商品查询的调用链，并在 IDEA 中按顺序指出对应方法。
- [ ] 在商品查询链路中放一次断点，观察关键词参数和返回列表。
- [ ] 手算一次优惠，再与计算器测试结果核对。
- [ ] 用自己的话解释事务、重复提交保护和库存竞争，分别解决哪一种错误。
- [ ] 能说明浏览器通过 HTTP 与 Java 服务器通信，JSON 是传输格式；浏览器并不直接操作 MySQL。

手算示例：指定原价 4000 元、商品折扣 0.90、金卡折扣 0.95、折后满 3000 减 100，得到 4000 → 3600 → 3420 → 3320 元，会员积分为 3320。这个示例使用的是明确指定的条件，不表示你当前后台配置一定如此。

完成标准：合上 AI 的解释，你仍能用自己的例子讲清楚这一小段，而不是只能复述术语。
