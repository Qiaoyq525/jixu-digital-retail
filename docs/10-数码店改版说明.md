# 极序数码改版说明

这次改版把课程项目的经营场景调整为电子产品门店。店名统一为 **极序数码 / JIXU DIGITAL**，老板姓名为 **乔胤淇**，界面称呼 **乔先生**。登录用户名继续使用 `admin`，网站密码不因显示名调整而改变。

## 页面与业务背景

四类商品为手机通讯、电脑整机、智能穿戴、显卡硬件。商品描述显示型号、内存、存储、尺寸等参数，登录页、商品卡片和工作台使用电子设备视觉。商品仍通过 Java 后端查询和保存到数据库，页面不是一套独立的静态演示数据。

当前按型号管理商品数量，没有逐台设备序列号、保修工单、真实支付或外部商城接口。售后沿用整单退货退款，退款恢复库存并回退原订单积分和净消费。

## 会员和优惠

等级由净累计消费推导；退款会回退净消费，因此也可能降低等级。

| 支付前净累计消费 | 等级 | 会员折扣 |
|---|---|---|
| 小于 5000 元 | 普通会员 | 原价 |
| 满 5000 元、小于 15000 元 | 银卡会员 | 98 折 |
| 满 15000 元、小于 30000 元 | 金卡会员 | 95 折 |
| 满 30000 元 | 黑金会员 | 9 折 |

一次订单按“全场折扣 → 支付前会员等级折扣 → 折后满减”计算，每步保留两位小数。新库默认全场折扣为 1.00，满减为满 3000 元减 100 元；满减每单满足条件时减一次，不按整数倍累加。获得积分为实付金额向下取整。

例如零消费的会员在默认优惠下买一台 5499 元的 iPhone 16：本单按普通会员计算，实付 5399 元，获得 5399 积分，支付后升为银卡。下一笔订单才应用银卡折扣。若整单退款，则按原单退回 5399 元，撤回 5399 积分和对应净消费。

## 已有数据库怎样升级

本轮追加 `V2__upgrade_to_digital_store.sql`，保留 V1 文件及其校验和。Flyway 在应用启动时执行尚未应用的迁移，随后 Java 再判断是否需要创建首次演示资料。已有用户时不会重新批量初始化账号和商品。

旧演示商品通过“旧 SKU 和旧名称同时匹配”识别，直接更新原行的 SKU、名称、描述、售价和图标。旧分类和供应商也按已知旧名称条件更新。目标 SKU 或目标名称已经存在时跳过相应更新，避免唯一键冲突。

迁移保持以下资料：

- 商品主键、当前库存、上架状态、低库存阈值和创建时间。
- 已有订单、订单明细中的成交名称与单价快照。
- 采购明细、库存流水、购物车、排队票据及其关联关系。
- 会员积分、累计净消费和积分流水，以及已有密码哈希。

用户新建的商品以及改过名称、不再匹配旧演示名称的商品会保持原样。如果仅调整了旧演示商品的价格或描述，但仍保留旧 SKU 和旧名称，这件商品仍会按演示映射升级。旧购物车保留原商品编号，后续试算按升级后的当前售价进行；旧订单仍显示成交时的名称和售价。不要把历史杂货订单改写成数码销量。

旧库只有在满减门槛和金额同时仍是旧默认的 `100.00 / 10.00` 时，才成组调整为 `3000.00 / 100.00`。管理员自行修改过其中任意一项时保持原设置。老板账号的显示名按本轮要求改为乔胤淇，用户名和密码不变。

## 从哪段代码开始理解

建议先在浏览器搜索一件设备，再在 IDEA 中沿着下面的顺序读：

1. `CatalogController.products(...)` 接收关键词和分类编号。
2. `CatalogService.list(...)` 确认当前角色，决定会员是否只看上架商品。
3. `CatalogMapper.list(...)` 绑定参数、查询 MySQL，得到商品对象。
4. `ApiResponse` 包装结果，Spring 把 Java 对象转成 JSON。
5. `static/app.js` 接收 JSON，把名称、参数、价格和库存显示在商品卡片。

看懂这条最短路径后，再看 `MemberLevel`、`DiscountCalculator`、`OrderService` 和 `QueueService`。先解释字段和方法，再解释 `@Transactional`、MyBatis 注解与线程池如何配合。更详细的逐段讲解见 [代码阅读与答辩详解](09-代码阅读与答辩详解.md)。
