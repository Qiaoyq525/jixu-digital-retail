# 运行与环境说明

项目交付位置为 `C:\Users\Q\Desktop\java\版本3`。初次使用 IDEA 的逐步操作见 [IDEA 打开与运行](08-IDEA打开与运行.md)；本文件解释工具分工、数据库与运行故障。

## 电脑上各个组件的分工

| 组件 | 当前用途 | 是否需要一直打开一个图形窗口 |
|---|---|---|
| IDEA | 阅读、编辑、调试 Java 项目 | 阅读调试时打开即可 |
| JDK 21 | 编译和运行 Java | 不需要手动打开 JDK 窗口 |
| Maven | 下载依赖、编译、测试、打包 | 由脚本或 IDEA 调用 |
| MySQL Server | 持久保存商品、订单、用户等数据 | 作为 `MySQL84` Windows 服务运行 |
| 浏览器 | 展示界面、发送 HTTP 请求 | 操作系统时打开 |

MySQL Configurator 是配置工具，安装结束点 Finish 后关闭属于正常情况。数据库服务正常运行就可以连接，不必反复打开安装向导。

本机工具位置：

```text
JDK：D:\mecodingtool\jdk-21
Maven：D:\mecodingtool\apache-maven-3.9.11
MySQL 程序：D:\mecodingtool\mysql-8.4
MySQL 实际数据：D:\mecodingtool\mysql-data\Data
MySQL 服务配置：D:\mecodingtool\mysql-data\my.ini
MySQL 本机地址：127.0.0.1:3306
```

本次实际检查的工具版本为 JDK 21.0.13、Maven 3.9.11、MySQL 8.4.13。`pom.xml` 选定 Spring Boot 3.5.16、MyBatis starter 3.0.4；MySQL Java 驱动的版本由 Spring Boot 依赖管理统一选择，不需要再手动复制一个驱动 jar 到项目目录。具体构建结果见测试记录。

电脑命令行原有默认 Java 是 8。运行本项目应使用已准备好的 JDK 21；启动脚本和 IDEA 的项目 SDK 都需要选择这个版本。不要仅凭命令行输入 `java -version` 的结果判断项目实际运行版本。

## 首次准备数据库

数据库名为 `my_shop_v2`，与版本1无关。初始化脚本只针对本项目数据库，不应删除电脑上的其他数据库。运行前可以先阅读 `scripts/setup-database.ps1`。已有可用本地配置与项目数据库时，无需再次执行初始化。

脚本需要管理员 `root` 的数据库密码来创建项目数据库和专用账号。密码在本地提示中输入，不写入 Java 源码、聊天、Git 或 SQL 日志。后端应用使用项目专用数据库账号，日常运行不使用 root。

建库与建表的分工：

1. 初始化脚本创建数据库、项目连接账号及本地连接配置。
2. Java 应用启动后，Flyway 根据 `src/main/resources/db/migration` 中的迁移文件建表。
3. 初始化数据逻辑在首次空库时加入演示分类、商品、账号和优惠设置。

迁移文件已经执行后，不要直接修改旧迁移内容并期待数据库自动重建。本轮数码店数据升级使用 `V2__upgrade_to_digital_store.sql`；以后再变更时追加更高版本文件。修改已有迁移可能造成校验和不一致，Flyway 会拒绝启动，以防代码和数据库结构悄悄偏离。

本地连接配置由初始化脚本管理，文件为项目根目录下的 `config/application-local.yml`。启动脚本和以项目根目录为工作目录的 IDEA 运行方式加载同一份配置。不要把包含数据库密码的配置加入提交或对外分享压缩包；演示代码时也无需展开这个文件。

## 用脚本启动

执行项目根目录的 `start.cmd`；如果正在 PowerShell 中，也可以执行：

```powershell
.\start.ps1
```

首次启动时 Maven 要下载 Spring Boot、MyBatis、MySQL 驱动等依赖。Maven 的本地 `repository` 用于缓存这些 jar 文件，它与 MySQL 的数据库数据目录是两回事。缓存以后不需要每次重新下载全部依赖。

浏览器访问 `http://localhost:8080`。Java 程序使用内嵌 Web 服务器，不需要额外安装 Tomcat。前端与后端由同一个应用提供，所以也不需要执行 `npm install`。

停止 Web 应用：在运行它的控制台按 `Ctrl+C`；也可双击 `停止脚本启动.cmd`，仅停止此项目以jar方式运行的进程。IDEA运行时使用红色停止按钮。这通常不会停止独立的 MySQL Windows 服务。

## 用 IDEA 阅读和启动

1. 通过 **Open** 打开 `C:\Users\Q\Desktop\java\版本3` 根文件夹，确认该文件夹中有 `pom.xml`。
2. 等待 IDEA 完成 Maven 同步。
3. 在 Project Structure 中将 Project SDK 和语言级别设为 Java 21。
4. Maven 的导入和运行 JDK 也选择 Java 21；Maven 可以选 IDEA 内置版本。
5. 运行配置的工作目录设为项目根目录，使用准备好的 `config/application-local.yml`。
6. 找到带 `@SpringBootApplication` 的启动类，运行 `main` 方法。

启动脚本能启动，并不意味着 IDEA 会自动选对 JDK 和工作目录。若 IDEA 提示缺少数据库密码，应核对本地配置是否存在、工作目录是否为完整项目根目录。

## 常见问题

| 现象 | 先检查什么 |
|---|---|
| `UnsupportedClassVersionError` | 实际运行 JDK 是否为 21 |
| Maven 无法解析依赖 | 网络、代理、Maven 仓库地址；不要随意删除整个本地仓库 |
| `Communications link failure` | `MySQL84` 是否正在运行，端口是否为 3306 |
| `Access denied for user` | 数据库账号、密码、允许连接的主机是否匹配 |
| `Unknown database` | 是否执行过首次建库脚本，库名是否为 `my_shop_v2` |
| 8080 已被占用 | 是否重复启动了两个 Java 应用；停止前一次进程或修改端口 |
| 页面提示登录过期 | 重新登录；会话在应用重启后可能失效 |
| 写操作返回 403 | 是否通过页面获取了新 CSRF token；不要通过关闭保护掩盖问题 |
| Flyway 提示校验失败 | 是否修改过已经执行的旧迁移文件 |

不要为解决登录问题直接关闭 MySQL 身份验证，也不要为本机开发开放公网端口。正式排查时先保留错误信息，再逐项确认原因。

## 网页账号与数据库账号

`admin`、`cashier1`、`member1` 是数码商城网站账号，存在 `shop_user` 表中。`root` 和项目专用连接账号是 MySQL 账号，用来控制程序如何访问数据库。网站老板不等于数据库 root，网站也不会展示用户原始密码。
